# Using two computers at one desk

**Question:** With a laptop and a desktop PC both running work, is it normal to use a second keyboard and mouse, or is there a standard way to share one set, and how do developers split the work between the two?

**Finding:**

- **Sharing one keyboard and mouse is the usual answer, not two sets.** Three routes appear in the sources:
  - **Software sharing over the network** (Mouse Without Borders, Input Leap, Synergy, Deskflow, ShareMouse): the pointer moves off the edge of one screen onto the other machine's screen, and the clipboard is shared. Each machine keeps its own display, so nothing is switched. Mouse Without Borders is free, Windows-only and part of Microsoft PowerToys. Input Leap and Deskflow are free and open source; Synergy is paid and cross-platform. ShareMouse's free tier is limited to two displays (vendor and comparison-blog sources).
  - **Hardware KVM switch:** one button or hotkey moves one monitor, keyboard and mouse between machines; no network and no software. It fits when both machines should use the same monitor. A monitor attached to the switch cannot also stay on another PC (comparison blogs).
  - **Remote desktop:** shows one machine's screen inside a window on the other. Sources frame it as for reaching a machine from elsewhere, not for switching at one desk.
- **Rule of thumb in the comparison blogs:** each machine with its own screen means software sharing; one shared screen means a hardware KVM; switching more than about five times a day favours a physical button (one vendor blog).
- **Mouse Without Borders details (Microsoft docs and Microsoft Q&A):** running PowerToys as administrator with "Use Service" lets it control elevated windows and the lock screen from the other computer, at higher security risk; file transfer has a 100 MB limit; clipboard and file sharing can be switched off; if the connection fails, the in-app firewall rule must be added on both devices. No latency figures were found.
- **Splitting the work for development (individual blogs):** a common pattern is to run the heavy workload on the desktop and use the laptop as the front end, through VS Code Remote SSH or VS Code Remote Tunnels. The host must stay on and awake; closing VS Code or the tunnel process ends the connection. One blog pairs this with tmux, SSH and Synergy, using the second computer as a "second monitor".
- **Laptop screen beside a PC monitor, each its own machine (the separate-screens case):**
  - **Input:** software sharing fits this case, because each machine keeps its own screen (comparison blogs, above). For two Windows machines the sources point to Mouse Without Borders. Switching is by moving the pointer off the screen edge, or Ctrl+Alt+1 to 4 or F1 to F4 (Microsoft docs in the Turkish locale and a news site; sources disagree on the lock-all shortcut, so read it from the PowerToys settings page).
  - **Network:** both machines must be on the same network and each needs the firewall rule added from inside PowerToys (Microsoft docs and Q&A). One third-party guide says Ethernet is best and Wi-Fi works with possible lag; no latency numbers were found.
  - **Known problems (user threads on Microsoft Q&A, 2026, unverified):** clicks failing on the second machine, fixed by restarting PowerToys on both and updating the older one; a disconnect while the Snipping Tool was used; a report that input only worked on one machine after the PCs slept (no authoritative guidance on sleep found); Ctrl+Alt+Del cannot be forwarded normally, and "Use Service" is Microsoft's answer for the lock screen and elevated windows. No comparison with Input Leap or Deskflow on Windows was found.
  - **Screen scaling:** Windows gives each display its own scale percentage; mixed resolutions (a laptop screen beside an external monitor) are a common cause of blurry apps. Dell's advice: close and reopen a blurry app rather than dragging its window across, or set a per-app high-DPI override. This applies within one machine; on two machines each keeps its own scaling, so it matters only if the same machine drives both screens.
  - **Ergonomics (university and campus safety offices, vendor white papers; no OSHA or CCOHS page was found):** the top of the screen at or slightly below eye level and about an arm's length away, an external keyboard and mouse with the laptop raised on a stand, and input devices at about elbow height. A laptop screen at a good height has its built-in keyboard too high, which is why an external keyboard is advised. Lower the screen somewhat for progressive or bifocal lenses.
  - **Setup steps (Microsoft's Mouse Without Borders page, read in full, 2026-11-23):** install PowerToys on both machines (Windows 10 2004 or newer, or Windows 11; `winget install --id Microsoft.PowerToys --source winget`). On the first machine open Mouse Without Borders in PowerToys Settings and select **New Key**. On the second, enter that key and the first machine's name and select **Connect**. Then move the cursor past the screen edge to switch; drag the device icons to match the real desk layout. If it fails: same network, key and host name typed correctly, **Add a firewall rule for Mouse Without Borders**, then **Refresh connections**. Settings of note: **Use Service** (lock screen and elevated apps; needs PowerToys run as administrator; security risk), **Move mouse relatively** (may help with different resolutions), **Block mouse at screen corners**, **Easy Mouse** (edge switching, can require Shift or Control), **Share clipboard**; shortcuts are Ctrl+Alt plus a letter or number. The page gives no default values and no port numbers. Known issues listed there: files only singly and up to 100 MB (zip folders first); a full-screen Remote Desktop or VM window can stop the keyboard following the mouse (enable **Hide mouse at the screen's edge**); the cursor can be invisible on a machine with no physical mouse (plug one in or turn on Mouse Keys); some settings may need to match on both machines.
  - **What the Settings page looks like in practice (three screenshots from the user's Windows 11 machine, 2026-11-23; PowerToys version not shown, the laptop had 0.102.3101; anecdotal, one machine, before any pairing):**
    - **Activation** (Mouse Without Borders: On). **Encryption key** section: a **Security key** row with a text box holding the generated key and a **New key** button, the line "To set up, generate the key on one machine, and enter it manually on other machines", and below it **Host name of this device** with a copy icon. The Microsoft page calls the host name "Local machine's host name" and describes a **Connect** step with a computer name; neither a separate computer-name box nor a **Connect** button was visible in the first screenshots. The user then reported that expanding the arrow on the **Security key** row shows the places to enter the connection details, so the docs page matches the page after all, but the entry fields are hidden under that expander.
    - **Result (user report, 2026-11-23, same day):** the two Windows machines paired and the user could move the mouse and keyboard between them. The screenshots were from the laptop. No timing, latency or sleep test was reported yet.
    - **Device layout** ("Drag and drop a machine to rearrange the order"): four empty laptop icons with no machine names, a **Refresh connections** button, and **Devices in a single row: On** ("A two by two matrix is considered otherwise"). Empty icons are consistent with no machine paired yet (inference).
    - **Use Service: Off**, greyed out, with the banner "This setting can only be changed when running as administrator". It "runs in service mode, allowing MWB to control locked remote machines and system or administrator applications".
    - **UAC prompt freezes the other machine (user report and PC-agent check, 2026-11-23; anecdotal, one case):** the user started Core Temp (which asks for administrator rights) on the PC; the UAC prompt appeared, the PC looked frozen and the shared mouse could not move onto its screen. Read-only check from the PC session afterwards: no `consent.exe` and no Core Temp process left (prompt answered, declined or timed out), PowerToys `run_elevated=False`, Mouse Without Borders `UseService=False`, CPU 14%, no System-log errors. Reading: Mouse Without Borders runs non-elevated and cannot send input to the UAC secure desktop; this matches the docs line above that Use Service plus administrator mode is what reaches elevated windows (inference from those two facts, not tested after the change). Answering the prompt at the PC's own keyboard and mouse is the way out.
    - **Where the administrator setting is in PowerToys v0.102.3101 (two screenshots from the user, 2026-11-23; the machine was not named, the user's laptop had this version):** PowerToys **General** page, section **Startup & permissions**: **Run at startup: On**, then a row **Running as administrator** with a button **Restart PowerToys as administrator** (greyed out when PowerToys is already elevated) and, expanded, a checkbox **Always run as administrator** ("This setting can only be changed when running as administrator", ticked in the screenshot) and **Show a warning for functionality issues when running alongside elevated applications** (ticked). The earlier wording "Administrator mode / Run at user logon as administrator" is from older versions or from memory and does not match this version. The second screenshot (rest of General) shows only Appearance & behavior, Back up & restore and Diagnostics, no further admin setting. Order that follows from the banner (inference): click **Restart PowerToys as administrator** (one UAC click at that machine), tick **Always run as administrator**, then open Mouse Without Borders and look for **Use Service**, which was greyed out before elevation.
    - **Use Service on, then the shared mouse cannot reach the PC (PC-agent read-only check, 2026-11-23, about 15:40; anecdotal, one case):** after the user switched Use Service on at the PC, the shared mouse no longer reached it. The service `PowerToys.MWB.Service` was Stopped, nothing listened on TCP 15100 or 15101, the service exe sat under a per-user AppData install (not Program Files), and the laptop answered ping from the PC (network fine). Docs search the same day (standard search, snippets only): Microsoft says the service runs under the System account and needs PowerToys run as administrator; release notes for 0.70.1 say service mode may be switched off after an upgrade, and another release notes that a changed install path can leave the service pointing at the wrong place, and that a toast appears when the service cannot start and Mouse Without Borders falls back to non-service mode. The official installer page says per-user and machine-wide builds have identical functionality (its list of differences was cut off in the results), and mixing the two is not supported. **No source was found that says a machine-wide install is required for the service**; the per-user path as the cause is a guess (inference), not tested. **Resolved (user report, same day; anecdotal):** the user turned Use Service off and restarted PowerToys at the PC, and mouse switching worked again; nothing else was changed. Use Service stays off, so the UAC-prompt freeze from the entry above remains: answer the prompt at the PC's own keyboard and mouse. Retrying the service (machine-wide install, or run as administrator first) is untested.
    - **Behavior, defaults seen:** Share clipboard On (hint: "If share clipboard stops working, Ctrl+Alt+Del then Esc may solve the problem"); "Transfer copied files to the remote machine's clipboard (up to 100 MB)" shown as a partly filled checkbox; Validate remote machine IP Off; Same subnet only Off ("only works when both machines have IPv4 enabled"); Block screen saver on other machines On; Show clipboard and network status messages Off. **Easy Mouse: Enabled** (can be set to Shift or Ctrl). Ignored fullscreen applications and Keyboard shortcuts are collapsed.
    - **Advanced settings:** **IP address mapping**, a text box that "resolves machine's IP address using manually entered mappings" (example line `MyLaptop 192.168.0.24`), which is a way round a computer name that does not resolve. **Troubleshooting:** **Add a firewall rule for Mouse Without Borders** (opens an external link) and **Show the original Mouse Without Borders UI: Off** (needs a restart).
  - **First use, same day (user reports; anecdotal):** clipboard text sharing worked between the machines. The laptop screen sat slightly lower than the monitor. With **Move mouse relatively** still off, the pointer appeared briefly at the top of the screen on switching and then moved to the expected place.
    - **Cursor appearing at the top (candidate causes, not a confirmed fix):** Microsoft's page describes **Hide mouse at the screen's edge** as positioning the cursor of one machine at the top edge when switching to another, so a brief top-of-screen cursor may be that setting working as designed (inference; whether it was on was not checked, it sits under the collapsed **Mouse behavior** group). The page says **Move mouse relatively** "may help" with different resolutions or multi-screen setups. Separate Windows forum threads report cursors jumping to a corner when a laptop and a monitor have different resolutions, and one names the Windows setting "Ease cursor movement between displays" (later checked: see the correction below; it does not apply here); a free tool (LittleBigMouse) is suggested for size and alignment mismatches. No Mouse Without Borders issue matching the exact symptom was found. Suggested order, one change at a time (inference): look at **Hide mouse at the screen's edge**, then **Move mouse relatively**. Both were tried and did not remove the flash (below).
    - **Mismatched screen heights (university safety offices, two of them with identical wording; vendor guides):** "Place the monitors at the same height. This can be a challenge if the monitors are different sizes or have different frames. In this case, align the tops of the monitors." The top of the screen at or slightly below eye level; the monitor used most directly in front of the keyboard. No source gives a tolerance for a small height difference, and none tested a laptop beside a monitor.
    - **Testing sleep and lock only when a fault appears (inference):** reasonable, because both machines keep their own keyboards as a fallback. Fixes named in Microsoft's page and the settings page: **Refresh connections**, restarting PowerToys on both, and "Ctrl+Alt+Del then Esc" (the settings page gives it for a stalled clipboard). With **Use Service** off, the lock screen of the other machine will not accept the shared keyboard (Microsoft docs), so a locked machine needs its own keyboard.
  - **Follow-up tests, same day (user reports; anecdotal):**
    - **Vertical alignment:** with a smaller laptop screen beside a larger monitor, the user observed that Mouse Without Borders maps the pointer by relative position (the middle of the monitor edge arrives at the middle of the laptop screen). No source documents how the tool maps the pointer between screens of different sizes (searched; only other tools and general mouse-warping papers came up), so this is the user's observation. Consequence (inference): to make the pointer's path match what the eye sees, align the vertical middles of the two screens, not their tops. This conflicts only with the safety-office advice "align the tops", which is written for screens driven by one computer, where Windows maps the pointer by physical overlap. It does not conflict with their eye-level rule if the monitor's top is at eye level and the smaller screen is centred on it, since its top is then lower ("at or slightly below eye level").
    - **Cursor flash on the PC side:** with **Hide mouse at the screen's edge** switched off, and then **Move mouse relatively** switched on, the pointer still appeared briefly at the top of the PC monitor on each switch to the laptop. Following the pointer onto the laptop screen showed nothing wrong; the flash was only on the machine being left. Searches found no PowerToys issue matching this symptom. Related items found: PowerToys issue 29700 (leftover cursor images; a commenter's workaround was to switch **Draw mouse cursor** off and on again on the other machine, "not a permanent fix"); a Microsoft Q&A answer that calls occasional cursor flicker a known side effect of the tool checking connection status (community answer, no source cited); PowerToys 0.102.3101 is reported to fix Mouse Without Borders connection problems (trade press); a Microsoft Q&A answer says a PowerToys version mismatch between machines causes failures (update the lagging machine). No fix for the flash was found; it looks cosmetic (inference).
    - **Correction on the Windows setting:** "Ease cursor movement between displays" lives under Settings > System > Display > Multiple displays and was added in Windows 11 build 22557 (guides). Guides disagree on whether it is on by default, and several users report not seeing it. The user's Multiple displays page shows only "Remember window locations based on monitor connection", "Minimize windows when a monitor is disconnected", "Detect other display" and "Connect to a wireless display". The setting governs screens attached to one computer, and here each machine drives one screen, so it does not apply; naming it earlier was off target (inference).
    - **Lag on the machine without the physical mouse:** the pointer felt laggy on the laptop screen when driven from the PC's mouse. No confirmed fix was found. The one close match is a PowerToys issue (version 0.70.0, two PCs) where movement on the connected PC was "very laggy" when the host mouse moved faster, with **Move mouse relatively** switched on because the monitor setups differed; the user here had also switched that setting on. A Microsoft Q&A answer suggests generating a **New key** and reconnecting if the connection shows as connected but input misbehaves. Nothing found compares Wi-Fi with Ethernet for this tool (the third-party guide quoted earlier says Ethernet is best). Suggested order (inference): switch **Move mouse relatively** off and retest, check both machines run the same PowerToys version, put the laptop on Ethernet or a 5 GHz connection close to the router, then generate a New key.
  - **Task Manager opens on the laptop while the mouse is on the PC (user report, 2026-11-23; anecdotal):**
    - **Closest match found:** one Steinberg forum thread (a user with Mouse Without Borders on two PCs) reports that with the mouse on one PC, Ctrl+Alt+Delete opened Task Manager on the other PC; the poster concluded the tool passes some key combinations between machines and posted no solution (forum post, search snippet only). The same thread reports a second symptom, input on the second machine acting only after the mouse moved onto it.
    - **What the docs say:** Windows treats Ctrl+Alt+Del as a secure attention sequence, so it never reaches an app in the normal way (a vendor guide's explanation, not Microsoft's). Microsoft's answer for the lock screen, elevated windows and Ctrl+Alt+Del is **Use Service**, which needs PowerToys run as administrator. The settings page's hint "Ctrl+Alt+Del then Esc" is given only for a stalled clipboard. No Microsoft page or PowerToys issue was found that covers Ctrl+Alt+Del or Ctrl+Shift+Esc opening Task Manager on the wrong machine, and the exact key combination the user pressed was not stated.
    - **User test results (same day, anecdotal):** Ctrl+Shift+Esc opened Task Manager when the mouse was on the laptop screen and did nothing when the mouse was on the PC screen; Ctrl+Alt+Del opened it on the laptop from either screen. The PC then turned out to be stuck (frozen), so the PC-side Ctrl+Shift+Esc result cannot be read as a Mouse Without Borders fault until retested on a healthy PC (inference). Ctrl+Alt+Del on the laptop from either screen matches the forum report above.
    - **No automatic reconnect after the PC restarted (user report, same day; anecdotal):** after the frozen PC was restarted, sharing did not resume by itself. A search found no official statement about reconnecting after a reboot and no PowerToys issue for it. Workarounds in Microsoft Q&A answers (community, not authoritative): close PowerToys fully (tray included) on both machines and reopen it; read the device status colour on the Mouse Without Borders page; fill **IP address mapping** (name, then IP) when a name does not resolve; add the firewall rule by hand for the `PowerToys.MouseWithoutBorders` executable; and, for the error "only one usage of each socket address", a 2024 post suggests a custom TcpPort registry value plus `netsh winsock reset` on both machines (unofficial, changes system networking). Likely first checks (inference): PowerToys running in the PC's tray after login, **Run at startup** on, same version on both machines, the PC's network profile (a Private profile is needed for the firewall rule to apply, inference), then **Refresh connections**.
    - **Resolved (user report, same day; anecdotal):** turning on PowerToys **Run at startup** on the PC fixed it; after that, sharing resumed on its own at each login. So the cause was PowerToys not starting after the reboot, not the pairing key or the network. This is the user's single observation on one machine; no source says Run at startup is off by default. Consequence (inference): on both machines, set Run at startup on before relying on the sharing, and expect the PC's login screen to need its own keyboard unless **Use Service** is on.
    - **Debug order (inference, not a source):** (1) note which keys were pressed, and on which keyboard: a laptop's own keyboard always acts on the laptop, so only the shared keyboard counts; (2) test Ctrl+Shift+Esc and Ctrl+Alt+Del separately with the mouse on the PC, and see which opens Task Manager on which machine; (3) confirm both machines run the same PowerToys version; (4) switch **Use Service** on (PowerToys as administrator, both machines) and retest, since Ctrl+Alt+Del is handled by the secure desktop; (5) press **Refresh connections** or generate a **New key** if the pointer and keyboard disagree about the active machine; (6) if only Ctrl+Alt+Del misbehaves, use Ctrl+Shift+Esc on each machine instead. A cosmetic or one-off key combination is not a reason to change tools.
  - **Is PowerToys (Mouse Without Borders) unreliable for serious use? (checked 2026-11-23; no data found, mostly anecdotal):**
    - **What exists:** Microsoft's docs present it as a shipped tool with a Known Issues list. Microsoft Q&A threads (2026) and PowerToys GitHub issues from versions 0.70 to 0.95 report connection failures, clicks failing on the second machine, leftover cursor images, lag, stuck modifier keys and disconnects; fixes in releases include 0.70.1 (a click landing on the wrong machine when switching; service mode possibly switched off after an upgrade) and 0.102.3101 (pairing failures introduced in 0.102.2933) (trade press and issue snippets). A version mismatch between the two machines is a repeated cause.
    - **What is missing:** no failure rate, no uptime or latency measurement, no independent comparison with Input Leap, Deskflow or Synergy on Windows, and no source calling PowerToys as a whole unreliable. A pile of problem threads is expected for any tool with many users and does not measure how often it fails (inference). The claim "easy to set up but not sustainable for serious use" is therefore neither confirmed nor refuted; it is a plausible reading of the problem reports, supported so far by one day of the user's own use (cursor flash, lag, wrong-machine Task Manager).
    - **Alternatives named, none tested here:** Input Leap and Deskflow (free, open source), Synergy (paid), Input Director and Multiplicity (suggested by one vendor roundup for all-Windows setups), a hardware KVM switch when one shared screen is acceptable. The roundup is a commercial vendor's blog.
    - **Open:** whether a different tool on this pair of machines would be better. The only way to know is a trial of one alternative on the same pair; nothing in the sources decides it.
  - **Layout that follows (inference from the points above, not a source):** one external keyboard and mouse, on the stationary machine's desk, shared with the other machine through Mouse Without Borders; the laptop open on a stand beside the monitor with its screen top near eye level, its own keyboard unused; both machines wired to the router where possible; PowerToys on both with the firewall rule added and "Use Service" on only if the lock screen or elevated windows must be controlled.
- **For agent sessions (inference, not a source):** because each machine's agents run locally on that machine, software sharing gives one keyboard and mouse across two screens while both machines keep running their own sessions. Remote Control (see `multi-device-agent-orchestration`) covers watching a session from the other machine's browser.

**Evidence strength:** vendor and comparison blogs plus Microsoft's PowerToys documentation (official for that tool's own behaviour); anecdotal for developer workflows. No head-to-head test, no latency or reliability data, and no survey of how common each route is.
