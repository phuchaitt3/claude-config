# Using two computers at one desk

**Question:** With a laptop and a desktop PC both running work, is it normal to use a second keyboard and mouse, or is there a standard way to share one set, and how do developers split the work between the two?

**Finding:**

- **Sharing one keyboard and mouse is the usual answer, not two sets.** Three routes appear in the sources:
  - **Software sharing over the network** (Mouse Without Borders, Input Leap, Synergy, Deskflow, ShareMouse): the pointer moves off the edge of one screen onto the other machine's screen, and the clipboard is shared. Each machine keeps its own display, so nothing is switched. Mouse Without Borders is free, Windows-only and part of Microsoft PowerToys. Input Leap and Deskflow are free and open source; Synergy is paid and cross-platform. ShareMouse's free tier is limited to two displays (vendor and comparison-blog sources).
  - **Hardware KVM switch:** one button or hotkey moves one monitor, keyboard and mouse between machines; no network and no software. It fits when both machines should use the same monitor. A monitor attached to the switch cannot also stay on another PC (comparison blogs).
  - **Remote desktop:** shows one machine's screen inside a window on the other. Sources frame it as for reaching a machine from elsewhere, not for switching at one desk.
- **Rule of thumb in the comparison blogs:** each machine with its own screen means software sharing; one shared screen means a hardware KVM; switching more than about five times a day favours a physical button (one vendor blog).
- **Mouse Without Borders details (Microsoft docs and Microsoft Q&A):** running PowerToys as administrator with "Use Service" lets it control elevated windows and the lock screen from the other computer, at higher security risk; file transfer has a 100 MB limit; clipboard and file sharing can be switched off; if the connection fails, the in-app firewall rule must be added on both devices. No latency figures were found.
- **Splitting the work for development (individual blogs):** a common pattern is to run the heavy workload on the desktop and use the laptop as the front end, through VS Code Remote SSH or VS Code Remote Tunnels. The host must stay on and awake; closing VS Code or the tunnel process ends the connection. One blog pairs this with tmux, SSH and Synergy, using the second computer as a "second monitor".
- **Laptop screen beside a PC monitor, each its own machine (the separate-screens case):**
  - **Input:** software sharing fits this case, because each machine keeps its own screen (comparison blogs, above). For two Windows machines the sources point to Mouse Without Borders. Switching is by moving the pointer off the screen edge, or Ctrl+Alt+1 to 4 or F1 to F4 (Microsoft docs in the Turkish locale and a news site; sources disagree on the lock-all shortcut, so read it from the PowerToys settings page).
  - **Network:** both machines must be on the same network and each needs the firewall rule added from inside PowerToys (Microsoft docs and Q&A). One third-party guide says Ethernet is best and Wi-Fi works with possible lag; no latency numbers were found.
  - **Known problems (user threads on Microsoft Q&A, 2026, unverified):** clicks failing on the second machine, fixed by restarting PowerToys on both and updating the older one; a disconnect while the Snipping Tool was used; a report that input only worked on one machine after the PCs slept (no authoritative guidance on sleep found); Ctrl+Alt+Del cannot be forwarded normally, and "Use Service" is Microsoft's answer for the lock screen and elevated windows. No comparison with Input Leap or Deskflow on Windows was found.
  - **Screen scaling:** Windows gives each display its own scale percentage; mixed resolutions (a laptop screen beside an external monitor) are a common cause of blurry apps. Dell's advice: close and reopen a blurry app rather than dragging its window across, or set a per-app high-DPI override. This applies within one machine; on two machines each keeps its own scaling, so it matters only if the same machine drives both screens.
  - **Ergonomics (university and campus safety offices, vendor white papers; no OSHA or CCOHS page was found):** the top of the screen at or slightly below eye level and about an arm's length away, an external keyboard and mouse with the laptop raised on a stand, and input devices at about elbow height. A laptop screen at a good height has its built-in keyboard too high, which is why an external keyboard is advised. Lower the screen somewhat for progressive or bifocal lenses.
  - **Setup steps (Microsoft's Mouse Without Borders page, read in full, 2026-11-23):** install PowerToys on both machines (Windows 10 2004 or newer, or Windows 11; `winget install --id Microsoft.PowerToys --source winget`). On the first machine open Mouse Without Borders in PowerToys Settings and select **New Key**. On the second, enter that key and the first machine's name and select **Connect**. Then move the cursor past the screen edge to switch; drag the device icons to match the real desk layout. If it fails: same network, key and host name typed correctly, **Add a firewall rule for Mouse Without Borders**, then **Refresh connections**. Settings of note: **Use Service** (lock screen and elevated apps; needs PowerToys run as administrator; security risk), **Move mouse relatively** (may help with different resolutions), **Block mouse at screen corners**, **Easy Mouse** (edge switching, can require Shift or Control), **Share clipboard**; shortcuts are Ctrl+Alt plus a letter or number. The page gives no default values and no port numbers. Known issues listed there: files only singly and up to 100 MB (zip folders first); a full-screen Remote Desktop or VM window can stop the keyboard following the mouse (enable **Hide mouse at the screen's edge**); the cursor can be invisible on a machine with no physical mouse (plug one in or turn on Mouse Keys); some settings may need to match on both machines.
  - **What the Settings page looks like in practice (three screenshots from the user's Windows 11 machine, 2026-11-23; PowerToys version not shown, the laptop had 0.102.3101; anecdotal, one machine, before any pairing):**
    - **Activation** (Mouse Without Borders: On). **Encryption key** section: a **Security key** row with a text box holding the generated key and a **New key** button, the line "To set up, generate the key on one machine, and enter it manually on other machines", and below it **Host name of this device** with a copy icon. The Microsoft page calls the host name "Local machine's host name" and describes a **Connect** step with a computer name; neither a separate computer-name box nor a **Connect** button was visible in these screenshots, so the labels or the layout in this version differ from the docs page (what sits under the Security key row's expander was not captured).
    - **Device layout** ("Drag and drop a machine to rearrange the order"): four empty laptop icons with no machine names, a **Refresh connections** button, and **Devices in a single row: On** ("A two by two matrix is considered otherwise"). Empty icons are consistent with no machine paired yet (inference).
    - **Use Service: Off**, greyed out, with the banner "This setting can only be changed when running as administrator". It "runs in service mode, allowing MWB to control locked remote machines and system or administrator applications".
    - **Behavior, defaults seen:** Share clipboard On (hint: "If share clipboard stops working, Ctrl+Alt+Del then Esc may solve the problem"); "Transfer copied files to the remote machine's clipboard (up to 100 MB)" shown as a partly filled checkbox; Validate remote machine IP Off; Same subnet only Off ("only works when both machines have IPv4 enabled"); Block screen saver on other machines On; Show clipboard and network status messages Off. **Easy Mouse: Enabled** (can be set to Shift or Ctrl). Ignored fullscreen applications and Keyboard shortcuts are collapsed.
    - **Advanced settings:** **IP address mapping**, a text box that "resolves machine's IP address using manually entered mappings" (example line `MyLaptop 192.168.0.24`), which is a way round a computer name that does not resolve. **Troubleshooting:** **Add a firewall rule for Mouse Without Borders** (opens an external link) and **Show the original Mouse Without Borders UI: Off** (needs a restart).
  - **Layout that follows (inference from the points above, not a source):** one external keyboard and mouse, on the stationary machine's desk, shared with the other machine through Mouse Without Borders; the laptop open on a stand beside the monitor with its screen top near eye level, its own keyboard unused; both machines wired to the router where possible; PowerToys on both with the firewall rule added and "Use Service" on only if the lock screen or elevated windows must be controlled.
- **For agent sessions (inference, not a source):** because each machine's agents run locally on that machine, software sharing gives one keyboard and mouse across two screens while both machines keep running their own sessions. Remote Control (see `multi-device-agent-orchestration`) covers watching a session from the other machine's browser.

**Evidence strength:** vendor and comparison blogs plus Microsoft's PowerToys documentation (official for that tool's own behaviour); anecdotal for developer workflows. No head-to-head test, no latency or reliability data, and no survey of how common each route is.
