# Wording for "last query row" and "fused SDPA attention" on a resume

- **Question:** A resume bullet says an attention-steering method (NNP) is applied only at the last query row of the prompt, while the rest of the prompt runs through PyTorch's fused attention. Which terms are standard, and does "optimized attention implementation" mislead?
- **Finding:**
  - **(a) The final position.** Papers on prefill speed-ups describe the same single-row computation as the *last prompt token's query* ("last-token query", "final prompt token's query", "last query row"); one notes that next-token prediction depends on the final hidden state; another aggregates over the *last n query positions*. The preprints say "last-token query" or "last query row"; neither is a fixed term of art. *Correction 2026-11-19:* this entry first called "last token" the more common plain form; no source showed "common", and "last token" alone can mean the last token of the prompt rather than its query row. The user chose "last query row", which also matches the thesis code (a row of `q`).
  - **(b) The rest of the prompt.** PyTorch's `scaled_dot_product_attention` (SDPA) is one call that dispatches to three backends: FlashAttention, memory-efficient attention and a "math" fallback; the fused kernels avoid materialising the full score matrix, which is why memory falls. The official wording is "fused kernels" for the first two; Hugging Face says SDPA "selects the fastest attention function" automatically. "SDPA" is the operation's name, not a speed claim.
  - *Checker's inference, wording:* "optimized attention (implementation)" implies the custom part is the unoptimized one and is vague about what is optimized; "fused" and "SDPA" are jargon for a first-time reader. The mechanism the reader can check against the result is memory: the fused path is *memory-efficient attention*, the name PyTorch itself gives one backend, and it explains "peak memory 2.9 to 1.2 GB". So "memory-efficient attention" describes the rest of the prompt without grading the steered part. Avoid "standard attention": in the literature it means the plain unfused version, the opposite of what ran.
  - *Backend that ran, checked three ways (2026-11-19; the thesis's own docs were not taken on trust).* (1) Thesis code: the hybrid path calls `F.scaled_dot_product_attention` with an explicit float mask (`attention.py`); thesis `docs/BENCH-BATCHING.md:98` says torch 2.1's memory-efficient kernel ran (a claim by the thesis author, so only supporting). (2) PyTorch 2.1.0 source `sdp_utils.cpp` (fetched through a summarising tool): the flash gate list includes `check_for_attn_mask` and `check_gpu_sm75_or_greater`; the memory-efficient gate list has no attn-mask check; default order is flash, then memory-efficient, then math. The body of `check_for_attn_mask` was not shown, but PyTorch's own warning text, quoted in (3), states it. (3) **Measured on the thesis laptop stack** (torch 2.1.0+cu118, GTX 1660 Ti, sm75; a seconds-long script, Qwen2.5-0.5B shapes, fp16 float mask, `sdp_kernel` forcing one backend): flash only fails ("No available kernel"; warning "Both fused kernels do not support non-null attn_mask"), memory-efficient only runs, math only runs. With flash impossible and the order flash, memory-efficient, math, the default dispatch is memory-efficient. Not measured: which kernel the default call picked (the profiler showed no CUDA kernel names), the real run's unaligned mask lengths, a T4, or torch 2.5/2.11 (a later thesis laptop run used 2.5.1, the Kaggle T4 2.11).
  - *Correction:* an earlier line here said Turing lacks FlashAttention support; wrong for torch 2.1.0, whose flash gate allows sm75 (the mask, not the GPU, rules flash out).
- **Evidence strength:** *documented behaviour* for the three SDPA backends (PyTorch blog and tutorial); *usage in papers* for "last-token query" (search summaries of preprints); *a measurement on the thesis laptop stack plus PyTorch 2.1.0 source* for the backend that ran; *no source* on how recruiters read either phrase.
- **Sources:**
  - [PyTorch blog, out-of-the-box acceleration](https://pytorch.org/blog/out-of-the-box-acceleration/): the three backends; fused kernels used when available.
  - [PyTorch SDPA tutorial](https://pytorch.org/tutorials/intermediate/scaled_dot_product_attention_tutorial): dispatch to FlashAttention or the C++ implementation.
  - [Hugging Face, attention interface](https://huggingface.co/docs/transformers/main/en/attention_interface): SDPA picks the fastest function.
  - [CLAA: Cross-Layer Attention Aggregation for LLM prefill](https://arxiv.org/pdf/2602.16054) and [Efficient LLM inference solution on Intel GPU](https://arxiv.org/pdf/2401.05391): last-token and last-n query positions; "customized SDPA kernel" (preprints; summaries only).
- **Limits:** Two standard searches read through search-result summaries, one source fetch read through a summariser, one small measurement; the official `scaled_dot_product_attention` reference page was not retrieved. The last-token claims come from preprints, not a glossary. Nothing here is about resumes or hiring; the wording advice is the checker's inference. ## Merged from `attention-steering-terminology` (2026-11-24): "Attention steering" vs "attention intervention"

*Original question: Is "attention steering" or "attention intervention" the right term for an inference-time method that edits attention scores?* Cite this section as `findings/attention-steering-terminology` (the old tag) or `findings/attention-prefill-terminology`.

- **Question:** For an inference-time method that changes a language model's attention scores (e.g. adds a bias to pre-softmax logits to up- or down-weight chosen context tokens), is "attention steering" or "attention intervention" the more correct and recognised term?
- **Finding:**
  - "Attention steering" is the established name for this family. PASTA ("Tell Your Model Where to Attend: Post-hoc Attention Steering for LLMs", Zhang et al., ICLR 2024) coined it for up-weighting the attention scores of chosen tokens and down-weighting the rest at selected heads, at inference, with no weight updates. Follow-ups (AutoPASTA; "Spotlight Your Instructions") keep the term for reweighting attention toward or away from spans.
  - "Intervention" is the broader umbrella: any inference-time change to internal activations (e.g. Inference-Time Intervention, which shifts head activations rather than attention scores). Some RAG papers call their method an "inference-time attention intervention" (CoDA, ACL Findings 2026), so the phrase is correct but less specific.
  - *Checker's inference:* a method that edits attention logits or weights toward or away from context tokens is attention steering, and that is the more searchable, recognisable term. "Intervention" is not wrong and suits a general description. One document should use one term for one method, or define the second as the same thing, so a reader does not take them for two techniques.
- **Sources:**
  - Zhang et al., "Tell Your Model Where to Attend: Post-hoc Attention Steering for LLMs", ICLR 2024 (peer-reviewed): https://arxiv.org/abs/2311.02262 , https://proceedings.iclr.cc/paper_files/paper/2024/hash/b99d6cc40b05809c3d84b57a165448cd-Abstract-Conference.html
  - "Pay Attention to What You Need" (Scaled ReAttention), arXiv 2307.13365 (preprint): https://arxiv.org/abs/2307.13365v3
  - CoDA, "Intervention for Mitigating RAG Hallucinations", Findings of ACL 2026 (peer-reviewed): https://aclanthology.org/2026.findings-acl.576.pdf
- **Limits:** Read through abstracts and search summaries. Usage is a matter of convention in recent papers, not a glossary from a standards body. No count of term frequency was made.
