# Subagent or new session: which to hand a task to

- **Question:** When a Claude Code chat hands work off to keep its own context small, when should it use a subagent and when a new session (a background session, `claude -p`, or another chat)? Should it use only one kind? Does the answer change how many to run at once?

- **Finding:**
  - **The docs pick by who coordinates and where the result goes, not by cost alone.** Anthropic's comparison page: subagents are "delegated workers inside one session that do a side task in their own context and return a summary". Use them when a side task "would flood your main conversation". Agent view runs background sessions that you "hand off" and "check back later", and they report "only to you". Agent teams (experimental) and dynamic workflows (a script holds the plan) cover larger coordinated jobs. "Running several sessions or subagents at once multiplies token usage" (official docs).
  - **Subagent:** its result comes back into the caller's context, so the caller grows by the size of each report. It runs inside the caller's session: an in-process teammate's background work "can't outlive the lead's process". Its prompt cache is separate, 5 minutes by default. A *fork* shares the caller's cache and context, so it is cheaper when the task needs that context, but it inherits the caller's model. A subagent can run on a cheaper model through `model`, and it compacts on its own (official docs).
  - **New session:** a background session (`claude --bg "<prompt>"`, agent view) is "a full Claude Code conversation that keeps running without a terminal attached", under a supervisor process. It survives the dispatching shell closing and machine sleep, but not a shutdown. It moves into its own worktree before editing, and it is told to commit and push its branch and end with a report naming the branch or PR. It "uses your subscription quota independently" and can start its own subagents. Agent view is a research preview (official docs). `claude -p` also starts a fresh session, and when signed in with a plan it still draws from subscription limits; a planned move to a separate credit was paused (official help article, update of 2026-10-07). Sessions talk through cross-session messaging, which carries plain text only, never history. A delivered message counts as usage, like a typed prompt (official docs). Nothing returns into the dispatcher's context unless it reads the result.
  - **Using only one kind.** No source says to use only one. The official page presents them as tools for different cases. Each has a failure mode when used for the other's case: a long or blocking job in a subagent ties up the caller and dies with it, and a short task in a new session pays a full cold start (CLAUDE.md, skill listing, tools) for a few tool calls. Practitioner guides draw the same split: subagents for in-session, summary-returning work, and separate `claude -p` processes for script-driven, parallel or CI work (anecdotal).
  - **How many at once is a separate question.** Token use scales with the number of active workers whichever kind is used (official docs). Parallelism buys wall-clock time, not fewer tokens, and pays only for independent tasks; coding has fewer of those than research (see `findings/long-agent-run-context`). The docs suggest 3-5 teammates for agent teams. They set no number for subagents or background sessions.
  - **Checker's inference for a self-paced loop:** use both. (a) A short task with a checkable finish (a fix plus its tests, minutes long) goes to a subagent in a worktree with a report of a few lines; the loop chat commits and opens the PR. (b) A long task (a measurement run, an hour or more, or work that should outlive the loop chat) goes to a background session that opens its own PR; the loop reads only the PR. (c) A task done in a couple of tool calls stays in the loop chat. Kind and number are separate choices. For the goal of fewer tokens, one worker at a time is enough. A second worker buys time and is worth it only when the tasks share no files and do not both need the GPU.

- **Evidence strength:** *official standard* for what each kind does, its lifetime, cache and usage (Anthropic docs and help article). *Anecdotal* for the practitioner split between subagents and `claude -p`. *No data found* comparing the tokens per finished task of the two kinds.
