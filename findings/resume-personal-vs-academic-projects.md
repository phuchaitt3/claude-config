# Personal vs academic projects on a new-grad resume

- **Question:** Do recruiters weigh a course project above a personal project? How should a project that started as a team course project and was later rebuilt solo be labelled and dated?
- **Finding:**
  - **No consistent ranking by label.** Some career guides say academic projects are the safe default for new grads, and one says they can count for more because they ran on a fixed schedule. Tech-focused guides say the opposite for generic coursework (class assignments do not belong on an engineering resume) and that the label matters less than what the project shows: relevance to the job, scope, results, linked code.
  - **Self-directed work with a real outcome can stand out more** than coursework (deployed app, measured result, users), while thin personal projects (another todo app) hurt. Polish and relevance decide, not origin.
  - **No source covers a solo rebuild of an earlier course project.** General date guidance applies: accurate ranges, no stretching dates to merge separate periods (see findings/resume-dates-revisited-projects).
  - *Checker's inference:* a rebuild in a new repository, by one person, with new code is a new project; labelling it "Course Project, Team of N" with the course dates would misstate who built it and when. The course origin can be stated in one phrase if it helps, and the course version stays a separate (or archived) entry with its own dates.
