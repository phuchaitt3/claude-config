# What LLM interview lists and entry-level certifications ask

- **Question:** For a first study page on LLM foundations, LLM inference and serving, and engineering-judgment scenarios: which topics recur, and which sources hold the standard answer?
- **Finding:**
  - **LLM foundations, tally over 8 public question lists** (a topic counts once per list if a question line matches a keyword): fine-tuning 8, attention or transformer 8, hallucination 7, evaluation 7, agents, tools or MCP 7, RAG 7, tokens 6, prompting techniques 6, embeddings 6, RAG against fine-tuning 6, latency 6, cost 6, context window 5, monitoring or drift 5, temperature or sampling 4, encoder against decoder 4, RLHF or alignment 4, sensitive data 4, versioning, canary or A/B 4, prompt injection or jailbreak 3, structured output 3, caching 3.
  - **Entry-level certification syllabi agree on the core.** AWS Certified AI Practitioner names tokens, chunking, embeddings, vectors, prompt engineering, transformer LLMs, foundation models, token pricing, context engineering, agents and MCP, hallucination and nondeterminism, inference parameters such as temperature, RAG, the cost trade-off between pre-training, fine-tuning, in-context learning, RAG and distillation, few-shot and chain-of-thought, prompt attacks (exposure, poisoning, hijacking, jailbreaking), RLHF, and evaluation by human review, benchmarks, ROUGE, BLEU, BERTScore and LLM-as-a-judge. Its scored weights: AI and ML basics 20%, generative-AI basics 24%, applications of foundation models 28%, responsible AI 14%, security and governance 14%. NVIDIA NCA-GENL (associate): core ML and AI 30%, software development 24%, experimentation 22%, data analysis 14%, trustworthy AI 10%; topics include RAG, embeddings, prompt engineering, RLHF awareness and benchmarking.
  - **Inference and serving is asked far less in general lists.** Batching and TTFT appear in 1 of the 8 lists, KV cache, quantization, speculative decoding and model parallelism in 2 of 8; "reduce latency" and "reduce cost" scenarios in 6 of 8. The topics come from specialised sources: a 17-card serving interview page and NVIDIA's inference-optimization article, which NCA-GENL lists as suggested reading (prefill against decode, batching and in-flight batching, KV cache and its size, model parallelism, PagedAttention, quantization, distillation, speculative inference).
  - **Standard answers, inference:** prefill is parallel and compute-heavy, decode is one token at a time and memory-bandwidth-bound (NVIDIA); static batching waits for the longest request, in-flight (continuous) batching evicts finished sequences and starts new ones at once (NVIDIA, Anyscale); KV cache grows linearly with batch size and sequence length (NVIDIA); a 7B model in 16-bit is about 14 GB of weights and its KV cache about 2 GB for one 4,096-token sequence (NVIDIA, Llama 2 7B); TTFT generally includes queueing, prefill and network time and grows with the prompt, ITL (also TPOT) is the average time between later tokens, and total latency is TTFT plus generation time (NVIDIA); as concurrency rises system tokens per second rise until saturation while tokens per second per user fall (NVIDIA); output length dominates total latency (Databricks, 2023, small models and 512-token inputs); when the KV cache is full vLLM preempts and recomputes requests, and the remedies are more memory for the KV cache, fewer concurrent sequences or more GPUs (vLLM docs); tensor parallelism splits each layer across GPUs, pipeline parallelism splits by layers (vLLM, NVIDIA); long new prompts delay the first token, a stable prefix placed first allows prompt caching, and streaming shortens the wait for visible text (OpenAI docs).
  - **Standard answers, judgment:** in a major outage make the system work as well as it can before finding the root cause, keeping logs as evidence (Google SRE book); release a change to a small share of traffic and compare with a control (Google SRE workbook); postmortems are blameless (Google SRE book); retry with exponential backoff and jitter, shed load, degrade gracefully (Google SRE book); do not be afraid to launch without machine learning, design metrics first, keep the first model simple (Google Rules of ML 1, 2, 4); find the simplest solution and add complexity, including agents, only when needed (Anthropic). Public judgment prompts found in the lists: when not to use an LLM, API against self-hosting, a product manager who wants to ship with a 15% edge-case hallucination rate, a complex agent that scores 15% better against a simpler RAG pipeline, biased output in production, cost over budget, a benchmark that rises while users say it got worse. No multiple-choice judgment test for AI engineers was found.
  - **Security list:** OWASP Top 10 for LLM applications (2025): prompt injection first, then sensitive information disclosure, supply chain, data and model poisoning, improper output handling, excessive agency, system prompt leakage, vector and embedding weaknesses, misinformation, unbounded consumption.
- **Evidence strength:** *official standard* for the AWS and NVIDIA syllabi and for tool behaviour in the vendor's own docs; *vendor or single source* for serving numbers; *sample or survey* for the tally (8 lists found by search, not drawn at random); *no data found* for what any particular employer's test asks.
